# 常见问题排查

遇到问题时，先找到与你看到的现象最接近的小节，再按顺序检查。任何情况下都不要向他人发送完整 API 密钥、登录密码、系统管理访问令牌、验证码或备用码。

## 先做四项通用检查

1. 确认当前登录的是正确的 workbar 账号；
2. 打开“API 密钥”，确认工具使用的密钥已启用、未过期且没有耗尽单独额度；
3. 打开“钱包”，确认当前余额正常；
4. 打开“使用日志”，按发生时间查找对应请求。

有日志时，优先保存请求 ID、模型、时间和错误文字。完全没有日志时，问题更可能发生在工具配置、网络连接或请求到达 workbar 之前。

## 无法注册或登录

### 提示用户名或邮箱已存在

- 确认是否已经注册过，并尝试从登录页使用“忘记密码”；
- 邮箱会按规范化后的形式检查，改变大小写通常不能创建另一个账号；
- 自行注销不会自动释放原用户名和邮箱，需要继续使用时请联系管理员。

### 收不到邮箱验证码或重置邮件

1. 检查邮箱拼写；
2. 检查垃圾邮件、广告邮件和拦截规则；
3. 不要在倒计时结束前反复点击发送；
4. 等待片刻后只重试一次；
5. 仍然收不到时，记录发送时间和邮箱服务商后联系管理员。

不要提供邮箱密码。

### 双重身份验证码无效

1. 把手机和电脑时间设置为自动同步；
2. 确认使用的是 workbar 对应的验证器条目；
3. 等待新一组验证码出现后再输入；
4. 验证器不可用时，使用一枚尚未使用的备用码。

### Passkey 无法使用

换到保存了该 Passkey 的设备或兼容浏览器重试，也可以改用密码登录。登录后可在“个人资料 → 安全”中重新注册 Passkey。更多说明请参阅[账号与安全](../account/account-and-security.md)。

## workbar Code 页面打不开

workbar Code 的本地页面地址是：

```text
http://127.0.0.1:3010/
```

看到“拒绝连接”通常表示本地 Code 程序没有运行，而不是 workbar 网站故障。

1. 启动 workbar Code；
2. 检查系统托盘中是否有 Code 图标；
3. 保持程序运行，再刷新本地页面；
4. 如果端口被占用，退出冲突程序后重新启动 Code；
5. 安全软件弹出运行或网络提示时，先确认程序来自官方来源。

`127.0.0.1:3010` 只用于打开本地 Code 界面，不能填写为模型服务的 Base URL。

## Code 一直停留在“连接到 workbar”

1. 在浏览器中打开 workbar 并确认已经登录；
2. 回到 Code，重新点击“连接 workbar”；
3. 在授权页点击 `Connect`；
4. 授权成功后页面会自动返回 Code。

连接提示消失即表示已进入主界面；如需确认状态，可以打开“设置 → workbar 账号”查看“已连接 workbar”。如果已经进入主界面，但密钥或模型仍未出现，先刷新或重新打开 Code；仍未出现时，打开“设置 → 模型 → 从 workbar 获取”，在弹窗中复制所需密钥并粘贴到 Key 列表，再点击“重新检测可用模型”。

Code 不需要你把登录密码或完整 API 密钥粘贴到聊天窗口。完整流程请参阅[使用 workbar Code](../tools/workbar-code.md)。

## 提示密钥无效、未授权或 `401`

按下面顺序检查：

1. 在 workbar“API 密钥”页面使用复制按钮，不要根据脱敏字符手动补全；
2. 在自己的工具中重新粘贴，确认前后没有空格、换行或引号；
3. 确认密钥已启用、未过期且仍有单独额度；
4. 确认工具需要的是 API 密钥，而不是登录密码或系统管理访问令牌；
5. 核对 Base URL、接口类型和身份验证格式，不要混用 OpenAI、Claude 与 Gemini 配置；
6. 如果密钥可能泄露，立即停用并创建新密钥。

### 停用密钥后怎样恢复

- 重启 AI 工具**不会**让已停用的密钥重新可用；
- 如果密钥只是你主动临时停用，而且确认没有泄露，可以先在“API 密钥”页面重新启用；
- 重新启用或替换密钥后，如果工具缓存了凭据或模型列表，再刷新配置或重启工具；
- 如果密钥疑似泄露，不要重新启用，应创建新密钥并在可信工具中替换。

不同工具的具体配置请参阅[连接其他兼容工具](../tools/compatible-tools.md)。不要把完整密钥发给管理员来验证。

## 请求被拒绝或出现 `403`

`403` 通常表示请求已到达服务，但当前凭据或限制不允许这次访问。检查：

- API 密钥是否设置了 IP 白名单；
- 当前公网出口 IP 是否在允许范围内；
- IP 或 CIDR 是否按页面要求填写；
- 所选分组是否仍对当前账号可用；
- 目标模型是否在密钥允许名单中；
- 工具是否使用了正确的接口格式。

不要为了临时排查而长期关闭服务器密钥的 IP 白名单。

## 工具中看不到模型，或提示模型不存在

1. 在[模型广场](https://workbar.ai/pricing)搜索目标模型，确认当前仍然可用；
2. 检查密钥使用的是自动分组还是固定分组；
3. 固定分组下，确认目标模型属于该分组；
4. 检查“高级设置 → 模型限制”是否排除了目标模型；
5. 确认密钥状态、单独额度和账号余额正常；
6. 在 AI 工具中刷新或重新同步模型列表；
7. 使用模型广场显示的准确模型名称，不要自行修改大小写或后缀。

模型限制留空只表示不额外缩小范围。目标模型仍须存在于固定分组或自动分组的可用范围中。详细说明请参阅[模型、分组与自动选择](../models/models-and-auto-routing.md)。

## 提示余额不足，或充值后余额未更新

“无限额度”只表示密钥没有单独额度上限，模型调用仍会消耗账号余额。

充值后仍提示余额不足时：

1. 刷新钱包；
2. 打开“订单历史”确认订单状态；
3. 确认 AI 工具使用的是同一账号下的密钥；
4. 待处理状态下不要重复付款；
5. 长时间没有更新时，保存订单号、支付时间和页面状态。

公开反馈中不要发送完整交易凭据、付款账号或二维码。充值和订单说明请参阅[余额、价格与使用记录](../billing/balance-pricing-and-usage.md)。

## 请求过于频繁或出现 `429`

1. 暂停片刻后再试；
2. 减少同时运行的任务数量；
3. 避免工具自动连续重试；
4. 把批量任务分段执行；
5. 检查是否有多台设备共用同一把密钥；
6. 在使用日志中确认请求量是否符合预期。

持续高速重试会延长故障并产生更多无效请求。

## 出现 `5xx`、服务暂不可用或请求中断

1. 保存错误文字、发生时间和请求 ID；
2. 等待片刻后只重试一次；
3. 在模型广场确认模型当前是否可用；
4. 使用自动分组时，确认密钥是否允许跨分组重试；
5. 按任务需要选择另一个当前可用模型；
6. 长任务反复中断时，缩短输入或拆成较小步骤。

跨分组重试可以增加后续尝试机会，但不能保证所有上游错误都能恢复。

## 返回内容异常，或使用日志中没有记录

先区分两种情况：

- **有成功记录但效果不理想**：写清任务、补充必要上下文，或选择更适合的模型；
- **有错误、退款或中断记录**：按记录中的状态和错误文字排查；
- **工具隐藏了原始错误**：查看工具终端、日志或详情；
- **完全没有服务端记录**：重点检查 Base URL、网络和工具配置；
- **日志筛选为空**：扩大时间范围，清除模型、分组、类型和密钥筛选。

不要把模型输出风格问题直接当作网关故障。可以先用一个简短、明确的请求验证基础连接。

## 费用或推荐奖励与预期不同

### 费用不同

核对日志中的模型、实际分组、输入与输出用量、计费类型和费用。自动分组按照后台顺序选择，不等于选择最低价。模型广场显示当前价格，历史请求应结合对应日志判断。

### 推荐奖励不同

- 受邀请者符合当前规则后，奖励直接进入自己的主余额；
- 邀请者的奖励先进入可转移状态，需要看到“转移到余额”按钮后手动确认；
- 累计收入是历史总计，不等于当前可转移金额；
- 奖励金额、条件和最低转移金额以钱包当前显示为准。

具体流程请参阅[余额、价格与使用记录](../billing/balance-pricing-and-usage.md)。

## 安全地提交问题

可以提供：

- 问题发生的准确时间和时区；
- 工具名称和版本；
- 模型名称；
- API 密钥在列表中的名称，或脱敏后的少量末尾字符；
- 完整错误文字；
- 使用日志中的请求 ID；
- 充值问题对应的订单号和订单状态；
- 已经尝试过的步骤。

截图前隐藏用户名、邮箱、头像、邀请链接、余额、订单信息和本地文件路径。

绝对不要提供：

- 完整 API 密钥或系统管理访问令牌；
- 登录密码；
- 邮箱验证码；
- 双重身份验证码、二维码、设置密钥或备用码；
- 完整付款凭据、付款账号或二维码；
- 私人项目源码或与问题无关的文件内容。

如果完整密钥已经出现在截图或聊天中，应立即停用并更换，而不是只删除消息。
